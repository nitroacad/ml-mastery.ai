Production RAG Architecture: Chunking, Hybrid Search & Reranking

Naive RAG systems suffer from chunk boundary fragmentation and keyword precision loss. Production architectures utilize multi-stage retrieval pipelines combining dense embeddings, sparse lexical search, and cross-encoder reranking.

1. End-to-End RAG System Flow

flowchart TD
    UserQuery[User Query] --> DenseEnc[Bi-Encoder Dense Vector]
    UserQuery --> SparseEnc[BM25 Lexical Tokens]

    DenseEnc --> DenseSearch[(Vector DB Search K=50)]
    SparseEnc --> SparseSearch[(BM25 Inverted Index K=50)]

    DenseSearch --> RRF[Reciprocal Rank Fusion RRF]
    SparseSearch --> RRF

    RRF --> TopK[Top 30 Candidates]
    TopK --> Reranker[Cross-Encoder Reranker]
    Reranker --> Top5[Top 5 Grounded Passages]

    Top5 --> LLMPrompt[LLM Generator]
    LLMPrompt --> GroundedResponse[Grounded Answer + Citations]

2. Reciprocal Rank Fusion (RRF) Algorithm

RRF combines rank lists from dense vector search and sparse keyword search without needing normalized scores:

Python RRF Implementation 
def reciprocal_rank_fusion(rank_lists, k=60):
    rrf_scores = {}
    for rank_list in rank_lists:
        for rank, doc_id in enumerate(rank_list):
            if doc_id not in rrf_scores:
                rrf_scores[doc_id] = 0.0
            rrf_scores[doc_id] += 1.0 / (k + rank + 1)

    sorted_docs = sorted(rrf_scores.items(), key=lambda x: x[1], reverse=True)
    return sorted_docs
